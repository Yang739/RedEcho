# RedEcho——红色旧址沉浸式互动演出

## 1. 项目概述
打造一款应用于红色旧址的思政教育小程序，通过**真人演员表演 + 游客实时投票决策 + AIGC生成内容**，让游客深度参与演出，并获取个性化纪念品。项目包含游客端与工作人员端（场务/演员）。

## 2. 用户角色
| 角色 | 登录方式                           | 核心权限                                     |
| ---- | ---------------------------------- | -------------------------------------------- |
| 游客 | 微信手机号一键授权                 | 阅读资料、参与演出投票、生成明信片、积分兑换 |
| 场务 | 手机号+密码/验证码（从游客端入口） | 创建/控制演出场次、发起投票/短片、管理活动   |
| 演员 | 同上（登录后识别演员身份）         | 接收AI台词建议、查看演出进度                 |

## 3. 游客端功能

### 3.1 首页（资料卡片）【当前实现】
- 资料内容：以「湖南主题红色史料」为精选内容源 `services/resources.js`（约 22 条，6 大分类：历史事件 / 湘籍伟人 / 红色旧址 / 湖湘精神 / 英烈丰碑），由前端直接读取，无需灌云数据库。
- 首页：从全库**随机推荐 3 张**卡片，点「更多 ›」进入资料中心。
- 为你推荐：优先推送**未读**资料；未读不足 3 篇时以已读补足，全部读完则继续随机；**点击卡片进入详情返回后不整体刷新，仅移除刚阅读的那篇并在列表尾部补充一篇（优先未读）**。
- 红色足迹（首页）：从本地阅读历史读取已读篇章，与「我的」页「我的阅读」**同源同步**，仅展示最近 3 篇；点「全部 ›」进入我的阅读列表页（`pages/read/read`）。
- 资料中心（`pages/resource/list`）：顶部分类筛选栏，展示该分类全部资料。
- 资料详情（`pages/resource/detail`）：正文 / 关键要点 / 名言；新增**相关宣传片占位**（短视频，定义为相关内容的简短宣传片，当前仅占位、未填实际内容）。
- **点赞功能已取消**（不再规划）；收藏、阅读积分等按原需求为后续扩展（详见《架构设计》/ 已知限制）。
### 3.2 演出模块
- **演出场次列表**：显示演出时间、主题、状态（即将开始/进行中/已结束）。
- **演出房间（核心互动）**：
  - 游客加入演出后，手机作为投票器和情绪反馈器。
  - **实时投票**：场务发布选择题，游客限时投票，结果以柱状图/弹幕实时显示。
  - **表情反馈**：可发送预设表情（鼓掌、流泪等）或快捷短语，可上大屏。
  - **短片观看**：场务推送历史短片，游客端同步播放。
  - **剧情分支**：根据投票结果，演员表演不同分支，系统记录每个人的选择路径。
- **演出回顾**：结束后可查看文字剧情总结和个人选择记录。

### 3.3 创作模块（AIGC明信片）
- 选择历史场景模板（如“井冈山会师”）。
- 自定义内容：
  - 系统提供名言警句库，支持手动输入（需敏感词过滤）。
  - 至少3种字体/布局可选。
- **AI生成明信片**：调用图像生成API，结合场景、名言、用户头像（可选）生成唯一图片。
- **现场打印**：
  - 连接蓝牙打印机或云打印服务，实现一键打印。
  - 若无硬件，可保存高清图至相册或分享。
- **我的明信片**：保存创作历史，可再次打印或分享。

### 3.4 我的（个人中心）
- 个人积分与等级（如“新兵”→“宣传员”）。
- 积分记录明细。
- **阅读收藏**：在资料详情页头图标题右侧点「收藏」五角星即可收藏当前篇章（再次点击取消，点击后五角星变黄），收藏状态本地保存；「我的服务」菜单「阅读收藏」进入收藏列表页（`pages/favorites/favorites`），展示全部收藏、点击回看详情、支持**右滑单条删除**（灰色删除键）或清空；统计「收藏」数随本地收藏实时更新（见 `services/favorites.js`）。
- **我的阅读（阅读历史）**：入口并入「我的服务」菜单，点击进入"我的阅读"列表页（`pages/read/read`），按时间倒序展示已读篇章、**每篇标注阅读时间（20XX 年 X 月 XX 日  XX : XX，24 小时制，灰色显示）**、点击回看详情、可清空、支持**右滑单条删除**（右滑露出灰色删除键，点击删除该记录）；记录仅存本机，清空缓存即丢失（见 `services/readHistory.js`）。
- **周边商城**：
  - 积分兑换/混合支付（预留微信支付）。
  - 兑换后生成核销码，现场核销。
- **工作人员入口**：验证手机号+密码/验证码，成功后切换至工作人员端视图。

## 4. 工作人员端功能

### 4.1 场务角色
- **演出管理**：创建/编辑演出场次、预设投票环节。
- **演出控制台（针对进行中的演出）**：
  - 环节控制面板：按顺序触发“开始投票”、“播放短片”、“结束投票”等。
  - 实时投票编辑：临时修改题目/选项，查看结果并锁定分支。
  - 短片推送：上传并推送给所有在线游客。
  - 观众情绪监控：实时显示表情统计，可控制是否投屏。
  - 现场活动发布：如答题抽奖，自动判分并发放积分。
- **历史演出记录**：查看过往场次数据、投票详情、剧情分支回放。

### 4.2 演员角色
- **我的场次**：显示待演场次、角色。
- **AI台词助手（核心亮点）**：
  - 演出中，实时接收基于当前环节、投票趋势、历史剧情生成的台词建议。
  - 可滑动查看多条备选文案，点击选用或自由发挥。
  - 台词支持文字显示，可选TTS语音预览。
- **台词本**：回看过往场次AI生成的台词。

### 4.3 数据看板（轻量）
- 当日游客人数、积分发放量、热门卡片、商城兑换Top榜。

## 5. 核心数据实体
- 用户表：ID，手机号，角色，积分，等级，创建时间
- 资料卡片表：ID，标题，内容，媒体URL，基础积分
- 阅读记录表：用户ID，卡片ID，阅读时间，获得积分
- 演出场次表：ID，标题，时间，状态，创建者
- 演出环节表：ID，场次ID，类型（投票/短片/活动），配置JSON，序号
- 投票问题表：ID，环节ID，问题，选项，正确分支（可选）
- 投票记录表：用户ID，问题ID，选项，时间
- AI台词建议表：ID，场次ID，环节ID，演员ID，文本，上下文提示词
- 明信片记录表：ID，用户ID，场景ID，名言，图片URL，创建时间
- 订单表：ID，用户ID，商品ID，支付方式，状态，核销码

## 6. 技术实现关键点
- **实时通信**：必须使用WebSocket（如腾讯云IM），保证投票、台词推送延迟<1s。
- **AIGC双应用**：
  - 明信片生成：调用文生图API（混元/Stable Diffusion），注意Prompt工程和图片后处理。
  - 台词生成：调用大语言模型API，结合投票上下文和角色背景，支持流式输出。
- **硬件交互**：蓝牙/云打印功能，这是极少数小程序会涉及的亮点。
- **演出状态机**：设计严格的状态流转，防止并发和误操作。
- **安全与权限**：工作人员双因子认证，防止游客越权。
- **数据可视化**：ECharts等展示投票实况和运营数据。

## 7. 非功能需求
- 投票响应 < 500ms
- 场务指令到游客端延迟 < 1s
- 明信片生成 < 10s
- 小程序分包：主包 + 演出分包 + 创作分包
- 适配中老年用户：可调整字体大小
